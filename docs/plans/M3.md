# M3 plan: Campaign Workspace and Campaign Setup

Build plan: [M3](../build-plan.md). Terms: Campaign, Campaign Workspace, Campaign Setup,
Tracked Empire, Fair Play, God Mode, Play Session (see [GLOSSARY.md](../../GLOSSARY.md)).

**Done when** (from the build plan): a fresh directory becomes a Campaign Workspace in one
guided conversation, and reading two saves leaves two archived extracts.

## Starting point (M0–M2)

- `workspace/config.py` has `CampaignConfig.load` (reads `campaign.yaml`: `save_dir`,
  `empire`, `mode`, `knowledge`; env overrides `HLIDSKJALF_SAVE_DIR` / `HLIDSKJALF_EMPIRE`)
  and `STATE_DIR = ".hlidskjalf"` for the turn log.
- `CampaignService` reads saves from `save_dir`, caches extracts in memory per file and
  mtime, logs tool results to `.hlidskjalf/turn-log.jsonl`.
- The extract header already lists `players` (name, country id, empire Display Name) and the
  `campaign` name, which is everything Campaign Setup needs to offer choices.
- Nothing writes `campaign.yaml` yet, nothing is archived, `skills/` is empty.

## Workspace layout

```
~/Stellaris/<campaign>/           # one directory per Campaign; Claude Code runs here
├── campaign.yaml                 # the Campaign Setup (written by the CLI, never by hand)
├── CLAUDE.md                     # short, generated: loads the skill for the chosen mode
├── archive/
│   └── 2259.12.25.json.zst       # Snapshot extract of the Tracked Empire, one per in-game date
├── saves/
│   └── 2259.12.25.sav            # backup copy of the save the extract was made from
├── predictions/                  # M9 (Coaching); created empty by setup so the layout is stable
└── .hlidskjalf/                  # machine state: turn-log.jsonl, blocks.jsonl (M7)
```

Decisions:

- **Key by in-game date.** Save file names in the game folder are already the in-game date
  (`2259.12.25.sav`), and the extract header carries the date. Archive and backup use the
  date as file stem. A second save of the same date (rare: manual save right after an
  autosave) replaces the first only if it is newer by modification time. Real save names
  that are not dates (e.g. `autosave_2259.12.25.sav`) are keyed by the header date, not the
  file name, so the archive is independent of naming.
- **Archive stores the compact extract (no per-planet detail)**: it is what `empire_overview`,
  `economy`, `compare` and Muninn need. Planet detail stays on-demand from the live save or
  the `saves/` backup. The stored JSON is the extract document unchanged (`schema` field
  included), compressed with `compression.zstd` from the Python 3.14 standard library — no
  new dependency.
- **Save backups are copies**, not moves; the game folder is read-only for us (CLAUDE.md
  scope rules). Backups let Muninn re-extract after a schema bump. They are the large part
  (tens of MB each), so `campaign.yaml` gets `backup_saves: true` (default) which the
  Player can turn off; the archive is always written.
- **Archive is written at read time.** `CampaignService.document()` already is the single
  place a save is turned into an extract; after a fresh extraction it calls
  `Archive.store(ref, doc)`. Cache hits do not write again. A failure to archive is logged
  into the turn log and added to the tool result's warnings; it never fails the tool call.
- **Muninn reads the archive, not the saves.** `Archive.list()` returns dates with
  header summaries, `Archive.load(date)` the document. The diff module works on those
  documents already (`diff_extracts`), so Muninn-style reads need no save present.

## `campaign.yaml` schema

```yaml
version: 1                        # schema of this file, for later migrations
save_dir: ~/.local/share/Paradox Interactive/Stellaris/save games/mpkonfderationvonvulkan_-2027490598
campaign: konfderationvonvulkan   # name from the save header, informational
empire: Plexxi                    # Tracked Empire: player name, empire Display Name or country id
mode: consulting                  # consulting | coaching; never switches on its own
knowledge: fair_play              # fair_play | god_mode
backup_saves: true
players:                          # everyone else who plays along (multiplayer); may be empty
  - name: Friend1                 # player name as in the save
    relation: ally                # ally | rival
```

- `empire` stays what it is today, so M2 code and workspaces keep working. `players` is new
  and optional; `relation` is validated (`ally` or `rival`), and each player name must exist
  in the newest save (checked by the CLI at write time, not by `load`, so a deleted save does
  not break the workspace).
- Unknown keys are preserved on rewrite (`raw`), so a Player's hand edits survive.
- `CampaignConfig.load` gains validation of `mode` and `players` and exposes `players`,
  `backup_saves`; existing tests keep passing because all new keys are optional.
- Fair Play / God Mode already steers `military`; the plan adds nothing there.

## Modules

- `workspace/config.py` — extended `CampaignConfig` plus `write_config(workspace, **fields)`
  (atomic write via temp file and rename; keeps unknown keys).
- `workspace/layout.py` — `create_workspace(path)` creates the directories, refuses a
  non-empty directory that is not already a workspace, `validate_workspace(path)` returns a
  list of problems (missing setup, save_dir gone, empire not in newest save, no archive yet).
- `workspace/archive.py` — `Archive(workspace)`: `store(doc, save_path)`, `list()`, `load(date)`,
  `has(date)`. Pure file handling; knows nothing about the extractor.
- `workspace/setup.py` — what the CLI needs: `list_campaigns(save_root)` (subfolders of the
  Stellaris `save games` folder with save count and newest date, from file names and mtimes,
  no parsing), `describe_save(save)` (players and empires from the header via the Extractor),
  `render_workspace_claude_md(config)`.
- `mcp/service.py` — archive hook in `document()`.

## CLI shape for the setup skill

The skill never writes YAML or parses saves itself; it calls these and relays the output
(JSON on stdout, errors on stderr with exit code 1):

| Command | Does |
|---|---|
| `hlidskjalf setup campaigns [--save-root PATH]` | lists Campaign folders in the Stellaris save folder: folder, campaign name, number of saves, newest save and its age |
| `hlidskjalf setup players <save_dir_or_save>` | reads the newest save of the folder, lists players with their empire Display Name and country id |
| `hlidskjalf setup write --workspace DIR --save-dir PATH --empire X --mode M --knowledge K [--ally NAME]... [--rival NAME]... [--no-backup]` | creates the workspace if needed, validates every choice against the newest save, writes `campaign.yaml` and `CLAUDE.md`; exit 1 with a plain message on any invalid choice |
| `hlidskjalf setup check [--workspace DIR]` | `validate_workspace`, prints problems; used by the skill at the end and by the generated `CLAUDE.md` |

`write` is idempotent: running it again with changed answers updates `campaign.yaml` and
regenerates `CLAUDE.md`, never touches `archive/` or `saves/`.

## Workspace `CLAUDE.md` template

Generated, short, English (the skill speaks the Player's language at runtime). Content:

1. One line: this directory is the Campaign Workspace of Campaign `<campaign>`; the Tracked
   Empire is `<empire>`; knowledge is `<fair_play|god_mode>`.
2. Mode routing: Consulting → use the `hlidskjalf:consult` skill for questions about the
   current game; Coaching → `hlidskjalf:coach` (not built until M9; the template says so and
   falls back to answering from tool results only). Retrospective questions → `hlidskjalf:muninn`.
3. The hard rules: every number and name comes from an `hlidskjalf` tool result; Display
   Names are used as returned; ask the Player to save again when `campaign_status` says the
   save is stale.
4. If `campaign.yaml` is missing: run `hlidskjalf:setup`.

The skill names `consult`, `muninn` are the ones M5 and M8 create; the template tests assert
the file names exist in `skills/` once they do, so a rename cannot silently break routing.

## Setup skill (`skills/setup/SKILL.md`, `hlidskjalf:setup`)

Guided conversation, one question per turn, in the Player's language:

1. Run `setup campaigns`; the Player picks the Campaign (or gives a path).
2. Run `setup players`; the Player says which empire is theirs.
3. Who plays along? For each other human player: ally or rival.
4. Mode: Coaching (the Player learns, even at the cost of this Campaign) or Consulting
   (best result now). Say plainly that it never switches on its own.
5. Fair Play or God Mode (what the two mean in one sentence each).
6. Run `setup write`, then `setup check`, then say what happens next ("save the game, then
   ask me anything").

Headless verification (last increment of M3): one `claude -p` run in a fresh temp workspace
with the answers scripted in the prompt and `HLIDSKJALF_USER_DIR`-style override pointing at a
temp save root that contains a copy of the reference `vulkan` folder (reference saves never
leave the machine; the temp copy lives under `/tmp`). Pass criteria: `setup check` is clean,
`campaign.yaml` holds the scripted choices, `CLAUDE.md` exists.

## Tests

- Config: round-trip, unknown keys preserved, invalid `mode` / `relation` rejected, env
  overrides still win.
- Layout: create in empty dir, refuse non-empty foreign dir, validate reports each problem.
- Archive: store → list → load round-trip with a synthetic document (no save needed); same
  date twice keeps the newer; a corrupt archive file is reported, not crashed on.
- Service: with the fixture saves, reading two saves leaves two archive files and two
  backups; deleting the original saves afterwards, `Archive.load` and `diff_extracts` still
  work (the Muninn-style read). Skips without reference saves.
- CLI: `campaigns` on a temp save root, `players` and `write` against a reference save
  (skip without), `write` rejects an unknown empire and an unknown ally name.
- Template: generated `CLAUDE.md` names the right skill per mode.

## Open points (no hold point; decided here, revisit only if wrong in practice)

- Archive key collisions across Tracked Empires: one workspace has one Tracked Empire, so
  the date is enough. Changing the `empire` in `campaign.yaml` later invalidates old extracts
  for Muninn's purposes; `setup write` warns and refuses unless `--reset-archive` is given
  (moves the archive to `archive.<n>/`, never deletes).
- Save-folder watcher is out of scope for v1; the archive fills when the Player asks.
