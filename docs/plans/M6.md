# M6 plan: Graph engine

Build plan: [M6](../build-plan.md). Terms: Solution Graph, Goal, Cause, Remedy, Obstacle, Key
Action, Vicious Circle, Actionable, Pending, Horizon, Crisis, Playbook Rule (see
[GLOSSARY.md](../../GLOSSARY.md)). The input is the Solution Graph JSON of
[M5.md](M5.md) (`graph/solution.schema.json`); this milestone changes nothing in it.

**Done when** (from the build plan): two Briefings with the same graph data render identically,
and the model never writes HTML. Publishing the page once as an Artifact is Julian's step (hold
point, `docs/awaiting-julian.md`); everything else is checked locally in headless Chromium.

## Division of labour

| Code (`engine/`, `graph/`) | Model (`hlidskjalf:consult`) |
|---|---|
| Lays the graph out and draws it, the same way every time | Writes the overlay; never HTML, CSS or JS |
| Marks Vicious Circles and model-added nodes from the data | Marks nodes `source: "model"` with a reason |
| Shows a node's evidence on click | Supplies `evidence`, `why`, `reason` as plain text |

The page is a fixed program that takes one data file. A Briefing differs from the next only by
`solution-graph.json`. That is also what makes "render identically" testable: same JSON in,
same positions and same pixels out.

## Page (`engine/index.html`, plus `engine/engine.js` and `engine/engine.css`)

One static page, no build step. Libraries from a CDN with **pinned exact versions and
Subresource Integrity hashes**: Cytoscape.js, ELK.js and `cytoscape-elk`. (Versions are chosen
in increment 2 and recorded in the file header and in `engine/VERSIONS.md` together with the
hashes; "latest" or a range never appears.) The page's own code is in `engine.js`, and the
Artifact bundle is `index.html` with that script and style inlined by a small
`tools/bundle_engine.py` (the Artifact is one file; the repo keeps three for readability). The
bundle step is deterministic and has a test.

### Data in

One function `loadGraph()` tries, in order, and stops at the first that yields JSON:

1. `<script id="solution-graph" type="application/json">` embedded in the page (used by the
   tests and by `briefing view`);
2. `?data=<url>` query parameter;
3. `fetch("solution-graph.json")` next to the page (how the Artifact reads its uploaded file;
   the exact upload mechanism is verified by Julian, see hold point);
4. a file picker and drag-and-drop, so any local file can be looked at.

The loaded document is checked against the fields the page needs (`schema === 1`, arrays
present, every edge endpoint exists). On failure the page shows the reason in plain text and
draws nothing; it never draws half a graph. All text from the JSON is inserted with
`textContent`, never as HTML (an `evidence` string with `<b>` shows the tags).

### Layout

Layered, left to right (ELK `layered`, direction RIGHT):

- **Goals** (Goal nodes) in the first layer, **Causes** in the middle layers, **Key Actions** in
  the last layer. Layer assignment is explicit, not inferred: ELK's `layerConstraint` with
  `FIRST` for Goals and `LAST` for Key Action Remedies. Everything else (Causes, Obstacles, the
  other Remedies) goes to the layers between, in the order the edges give.
- Edge direction in the data is Goal → Cause → Remedy → Obstacle → Remedy. The picture shows
  the same direction, and a Key Action sits at the right end even though in the data it hangs
  below its Causes. An edge from a middle node to a Key Action is drawn as it is in the data;
  the Key Action's `serves` list is additionally shown as thin dashed edges back to its Goals
  (only on hover or selection, to keep the picture quiet).
- Determinism: fixed ELK options (`elk.randomSeed`, `elk.layered.considerModelOrder.strategy`
  with the node order from the JSON, `elk.layered.crossingMinimization.semiInteractive` off),
  nodes and edges added in sorted id order, fixed node sizes computed from the label length by a
  pure function (no DOM measuring, because font metrics differ per machine), and fixed zoom
  and pan after layout (`fit` with fixed padding). No animation: positions are set directly.
- Vicious Circles: members of a circle get a colour per circle (a palette of colour-blind-safe
  hues, assigned in circle order), a thick outline and the circle name in the legend; the break
  point carries a marker. Edges between two members of one circle take its colour.
- Model-added nodes: dashed border and a "model" badge in the node and in the legend; the
  detail panel shows the node's `reason`.
- Status: Remedy `actionable` solid, `pending` hatched, `obstructed` greyed; Obstacle `present`
  red edge accent, `clear` muted, `unknown` and `judgement` open marker. Goal with `crisis`
  has a heavy outline. Every encoding also has a text label, so colour is never the only signal.
- The legend lists exactly the encodings that occur in this graph.

### Detail on click

Clicking a node fills a side panel: type, title, text, status, ratings (high/medium/low), the
`check_state` and the `evidence` strings, the Playbook Rule ids (the id only; rule text is in
the Briefing), `reason` for model nodes, which Goals it serves, which edges lead in and out.
For a Key Action also `rank`, `serves`, `unlocks` and `why`. Clicking a circle name in the
legend selects its members. The panel states only what is in the JSON.

### Header and lists

A header with empire, in-game date, game version and the counts (nodes, model nodes, circles,
Key Actions, pruned). Below the graph: the ranked Key Action list (click selects the node) and
the `pruned` list with reasons, so what the model cut is visible, not hidden.

### What is not in the page

No computed claims, no recomputation of status or ranking (the JSON is the truth), no
Benchmarks, no network access except the library CDN, no storage, no analytics.

## Tests

Headless Chromium is installed here (`/usr/bin/chromium`); no new Python dependency is needed.
`tests/engine_driver.py` runs `chromium --headless=new --no-sandbox --disable-gpu
--virtual-time-budget=… --dump-dom` against a temporary copy of the page with the graph
embedded (data source 1), and reads the result from a `<pre id="engine-state">` the page
writes after layout. The state is JSON: node positions and sizes, edge routes, colours per
circle, the visible text of the legend and the header. Screenshots use `--screenshot` for the
pixel comparison. Tests skip with a reason when no Chromium is found (like the golden tests
skip without saves), and never touch the network on their own: the driver rewrites the CDN
URLs in its temporary copy to files from a git-ignored cache `tests/fixtures/engine-libs/`
(filled by `tools/fetch_engine_libs.py`, which downloads the pinned versions and checks the
SRI hashes; running it is part of increment 2). A separate `-m network` test loads the real
CDN URLs once, so a broken pin or hash is caught.

Fixtures: small hand-made Solution Graphs (a Goal with a chain; two Goals sharing a Remedy; a
two-node Vicious Circle with break point; a model node; `obstructed`/`pending` Remedies; an
`evidence` string with `<script>` in it), plus a real one that the test builds itself with `expand_graph`
and `compose` from the vulkan mid-save and a fixed overlay (skipping without the saves).

- **Identical render**: same JSON rendered twice, and once with `nodes`/`edges` shuffled, gives
  the same `engine-state` (compared as JSON) and the same screenshot bytes. A different
  `date` or `empire` string changes only the header.
- **Layers**: every Goal's x is less than every Key Action's x; Causes lie between; no node
  overlaps another; every edge ends on its nodes.
- **Circles and model nodes**: each circle's members share one colour and differ from other
  circles; the break point is marked; a model node has the model marker and its `reason` in the
  panel state; a graph node has neither.
- **Click**: the driver clicks a node by dispatching the same event the page listens to and
  reads the panel state; evidence strings equal the JSON's.
- **No injected HTML**: the `<script>` evidence string appears as text and no extra script
  element exists.
- **Rejects bad data**: missing `edges`, an edge to an unknown id, `schema: 2` each give the
  error text and an empty graph.
- **Model never writes HTML**: static test over `skills/*/SKILL.md` and `src/`: the consult
  skill allows only the overlay file and the two CLI commands as outputs; no skill tells the
  model to write `.html`, `.js` or `.css`; `briefing compose` and `view` never accept HTML from
  the overlay (an overlay text is plain text; the Solution Graph schema has no HTML field, and
  a test checks that `compose` output through the page shows tags as text).
- **Bundle**: `tools/bundle_engine.py` output is byte-identical across runs and contains no
  reference to a local path; the unbundled and the bundled page give the same `engine-state`.
- **Pins**: every `<script src>` in `index.html` has an exact version in the URL, an
  `integrity` hash and `crossorigin`; a test fails on `@latest`, `@^`, `@~` or a missing hash.

## `briefing view` (local look, no publishing)

`hlidskjalf briefing view <solution-graph.json> [--port N]` copies the bundled page next to a
copy of the JSON in a temp directory, serves it from `127.0.0.1` only (stdlib `http.server`,
loopback bind, random free port by default) and prints the URL. It publishes nothing and
uploads nothing. The consult skill does not call it; it is for Julian and for the developer.
Test: the server answers 200 for the page and the JSON on loopback, refuses a path outside the
directory, and binds `127.0.0.1` (not `0.0.0.0`).

## Open risks

- **Headless layout differences.** ELK is pure JavaScript and deterministic for fixed options,
  but text widths differ per font. Node sizes therefore come from a pure function of the label,
  and the screenshot test runs on this machine only; it is skipped (position equality still
  runs) when `HLIDSKJALF_ENGINE_PIXELS=0`.
- **Artifact sandbox.** An Artifact may block the CDN, `fetch` of a sibling file or both. The
  page works from an embedded script or a picked file; whether the Artifact allows more is
  unknown until Julian publishes it once. Fallback: inline the libraries into the bundle (adds
  roughly 1.5 MB), decided after his report, not before.
- **ELK layer constraints on cyclic input.** Vicious Circles are cycles in the data; ELK breaks
  them internally, which may draw a back edge. The test uses a two-node circle and checks only
  that both nodes are placed and the circle is coloured; reversed-edge drawing is acceptable.
- **Large graphs.** A 6-Goal Briefing reaches about 100 nodes. The fixed sizes keep layout fast;
  the test with the biggest expansion records the layout time and fails above a generous budget.
- **Wide labels.** Titles are cut at a fixed length in the node and shown in full in the panel.
