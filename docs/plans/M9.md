## Division of labour

Same split as Ops and Debrief: what must come out identical every time is code, what needs language and judgement is
the model. The Coach is a language model that cannot be trusted to keep books, so every change to the Player Model, the
Hint Ladder, a Prediction or a Rendezvous goes through a script.

| Code (`src/admiralty/player/`, `src/admiralty/academy/`, MCP tools, CLI) | Model (`skills/academy/SKILL.md`) |
|---|---|
| Keeps the Player Model, the Hint Ladder, the Drill state, the Predictions and the Rendezvous; the only write path | Asks the question, reads the Player's answer, decides which outcome it was (see the table below), words hints in the Player's language |
| Finds the topics of a Snapshot (Crisis first), counts those waiting, hides the Mechanics Graph's answer until the Ladder reaches it | Never shows the Solution Graph; stays in question mode |
| Applies the fixed rules for Mastery Levels, drops and the patch rule | Names the level change openly when the tool reports one |
| Looks up where in the game a fact can be checked (curated table) | Says it; without an entry names only the domain |
| Detects decisions that are coming or happened (from Snapshots) | Asks for the one-sentence Prediction, proposes the check date |

The model's one judgement the rules depend on is the **outcome of an attempt**. It reports one of: `cause` (the Player
named the cause), `remedy` (named the remedy), `support` (a different answer; the tool checks it against the Snapshot
data), `miss`, `partial`, `full_explanation`, `escape_hatch`. The tool maps outcome plus Hint Ladder level to the Mastery
Level and refuses an outcome the state does not allow (a `cause` on a concept already at Evaluate). The model cannot
set a level.

## Decisions made while planning (Julian reviews them in the Abnahme)

1. **A concept is a Cause node** of the Mechanics Graph. The levels are defined by "found the cause", "a Snapshot shows
   the Remedy done" and "the cause reappears", so the Cause is the unit; its Remedies are the evidence of Apply, its
   Obstacles belong to the Remedies. Goals, Remedies and Obstacles have no level of their own. (The documents say "a
   node of the Mechanics Graph"; this narrows it. If Julian wants Remedies as concepts, the store keys do not change,
   only the topic builder.)
2. **A Remedy is "shown by a Snapshot"** only where the pack says how to see it. A new optional field `applied_when` on a
   Remedy (the same comparison shape as `pending_when`: a metric, an operator, a number or metric) marks it. Remedies
   without it cannot lift a concept to Apply; the Coach asks the Player instead and the answer stays Understand. Nothing
   is guessed (CLAUDE.md: no invented values). Coverage is part of the increment and reported. Language-free metrics were not enough, so the
   registry got one more kind, `contains` (1 when a Display Name is in a list of the extract, such as the taken
   Ascension Perks); the pack is written against the English game files.
3. **A Cause "appears" in a Snapshot** where the pack says so: a new optional field `present_when` on a Cause (the same
   comparison shape as `applied_when`) that is true while the Cause is there. Causes have no check of their own in
   `expand_graph`, so the field is the check; `player/evidence.py` evaluates it with `graph.metrics.evaluate`, the same
   function `expand_graph` uses. A Cause without it is "unmeasured": it never drops and cannot reach Create (which needs to see the Cause stay away). "Reappears in
   two Snapshots a year apart" means both show it and the in-game dates differ by 360 days or more. (Changed in 20c from
   "`expand_graph` reports the Cause with evidence", which does not exist for Causes.)
4. **Crisis level** is decided by the code from the Snapshot's resources (negative net with a stockpile that runs out
   within twelve months, as Debrief's `reserve_months` shows; energy, minerals, food, alloys and influence). One
   function, one threshold, documented in the module; the model may not declare a Crisis. Placeholder threshold
   twelve months, tuned on Julian's trial.
5. **Event store, not a mutable record.** The Player Model is the replay of an append-only `events.jsonl`; `model.json`
   is a cache that can be rebuilt. This gives the evidence log for free, makes "the Player Model changes only through
   the script" checkable (every change has an event with its reason) and lets the rules be tested by feeding events.
6. **Wiki list is empty until the licence is checked.** Increment 20g checks the licence of the official Paradox wiki
   and records the result in `docs/awaiting-julian.md`. Until then the list of reading tips stays empty and the Coach
   gives no link. The UI-location table is drafted from the game's own interface and localisation files only.

## Layout

```
<data dir>/player-model/            ~/.local/share/admiralty/player-model/ (ADMIRALTY_DATA_DIR moves the parent)
    events.jsonl                    append-only; one line per change, with campaign, in-game date, reason
    model.json                      cache: concept -> level, last change, drops, hatch uses
<workspace>/
    academy/
        drill.json                  the open Drill: topics, current topic, ladder level, Crisis flag
        drills.jsonl                closed Drills, one line each (summary, the dates each topic was raised)
        evidence.jsonl              the events of this Campaign (copy of the lines that came from here)
        rendezvous.json             the agreed date and save name, or none
    predictions/                    one JSON file per Prediction (the directory exists since M2)
```

`src/admiralty/player/` is the only code that writes under `player-model/`. `src/admiralty/academy/` holds the
Drill, the topics and the Predictions; it reaches the Player Model through `player/` only. Writes are atomic
(temp file, rename) and under a file lock, because the MCP server and the CLI may run at the same time.

## The fixed rules (the contents of `player/mastery.py` and `academy/ladder.py`)

Levels, from grilling topic 1 (R3 Q1, R4): `new 0`, `understand 1`, `apply 2`, `analyse 3`, `evaluate 4`, `create 5`.

| Event | Effect |
|---|---|
| `cause` at Ladder level 1 (question) or 2 (hint), conversation only | New → Understand |
| `cause` at level 3 (partial answer) or 4 (full explanation), `partial`, `full_explanation`, `escape_hatch` | stays New; Escape Hatch recorded with its Situation |
| `support` | counts as `cause`; the answer is noted as a candidate for the Mechanics Graph (`candidates.jsonl`) |
| Snapshot shows `applied_when` of a Remedy of the Cause, within five in-game years after the Coach raised it | Understand → Apply. Without a Snapshot showing it after five years: no change, and `ask_once` is set so the Coach asks what held the Player back |
| `cause` named before the Coach named the domain (open opening question, or the Player's self-assessment in Debrief) | → Analyse (needs Apply or better to have been reached once; otherwise Understand) |
| Chose between Remedies with reasons, or a Prediction on the concept came true | → Evaluate |
| Remedy applied twice without prompting and the Cause did not appear within five years | → Create |
| Cause present in two Snapshots at least 360 days apart, no Crisis in either | one level down; the tool reports it so the Coach says it openly |
| Patch: the Mechanics Graph of the new version differs in the formula (`facts`) or links of the Cause | → Understand (number-only changes keep the level) |

The Ladder: question, hint, partial answer, full explanation. One level up after a miss (two in a Crisis), back to
level 1 after a success. The Escape Hatch jumps to the top and is recorded. Evaluate or above: the topic is skipped.
Analyse: only open questions that do not name the domain.

Open points the fixed rules leave to the tests: what counts as "prompted" for Create (a Drill topic on this Cause in the
window means prompted); how `analyse` is proven when the Player never reached Apply (the table above says Understand
stays; written down as a test).

## Increments

Each is one commit, tests green, ruff clean, as in the Working Agreements.

- **20a. Store and single write path.** `player/store.py`: data dir via `ADMIRALTY_DATA_DIR`, events, replay, atomic
  append under a lock, `model.json` cache rebuilt on mismatch. `player/concepts.py`: the concept list from the loaded
  Mechanics Graph (Causes), keyed by id with version. A PreToolUse hook (`admiralty hook pretooluse`, registered in
  `hooks/hooks.json`) that blocks Write, Edit and Bash commands touching the `player-model/` path. Tests: replay equals
  cache, a broken cache is rebuilt, concurrent appends, the hook blocks the paths and lets others pass, an exception in the
  hook lets the call through (same rule as the Stop hook).
- **20b. Mastery rules.** `player/mastery.py`: pure `apply(state, event) -> (state, effects)` for every row of the table
  above except the Snapshot ones; patch rule with two Mechanics Graph versions built in the test from synthetic packs.
  Tests: one per row, plus the refusals.
- **20c. Snapshot evidence.** Schema field `applied_when` on Remedies and the curated pack filled where a metric says it
  (traditions adopted, buildings built, edicts, techs; metrics that exist today or are added to `metrics.yaml` with a
  source); coverage printed in the log. `player/evidence.py`: for a Cause, from two expansions, "Remedy shown", "Cause
  present", five-year window, 360-day rule, Crisis flag (decision 4). Tests with the vulkan saves (skip if absent) and
  synthetic documents.
- **20d. Hint Ladder, Escape Hatch, Drill state.** `academy/ladder.py` and `academy/drill.py`: `drill.json`, the attempt
  outcomes, ladder movement (one or two up, back to one), Escape Hatch event with the Situation, "next topic", end of
  Drill with the summary slot. Tests per rule. Done: a topic is over when cause and remedy are named, the full
  explanation was given (allowed on level 4 only, so the answer stays hidden until the Ladder reaches it) or the Escape
  Hatch was pulled; `raised` and `prompts` for `player/evidence.record_evidence` come from the open and the closed
  Drills (`drill.evidence_inputs`). Details in the module docstring.
- **20e. Topics.** `academy/topics.py`: from a Snapshot extract and the Player's own goal (asked at the first Drill and
  every Rendezvous; stored in `drill.json`), build the topic list with `expand_graph`: Crisis first, then by Key Action
  weight; skip Evaluate or above; open-question flag at Analyse; count of waiting topics without names. Fair Play: each
  topic marks whether hidden knowledge chose it; its `pointers` carry visible facts only (the extract's visible/full split
  decides); under God Mode they may carry everything. A test that a Fair Play topic list contains no hidden field.
  Done: Crisis Goals are expanded even when the Player did not name them; the Goals the Player named are kept in
  `drill.json` (`goals`); a topic never carries the Cause's title, description or Remedies, only the `concept` key. 20h
  must keep that key out of what the model sees until the Ladder reaches the answer (the id names the Cause). Details in
  the module docstring of `academy/topics.py`.
- **20f. Where in the game.** `knowledge/4.5.2/ui_locations.yaml`: per domain and key figure a path in the interface
  ("Outliner, top bar, tooltip of the energy icon") drafted from the game's `interface/` and localisation files; each
  entry cites its file. `academy/locations.py` looks it up (unknown figure: domain only). A lint test: every domain and
  figure exists in the Mechanics Graph's metrics and every entry has a source; the unknown-figure fallback. The list of
  wiki reading tips stays empty (decision 6) after the licence check is recorded.
- **20g. Predictions and Rendezvous.** `academy/predictions.py`: the fixed list of major decisions (war, ascension
  perk, tradition tree, megastructure, federation, redesignated world); detection before a decision from one Snapshot
  (Unity for the next tree, free perk slot) and after, by comparing two (new tradition tree, perk, war, federation,
  planet designation; megastructures where the extract shows them, otherwise named as not detectable), stored as
  hindsight; a Prediction is one sentence, a check date at most five years away, a state `open`, `confirmed`,
  `refuted`, `unclear`; the check reads the Snapshot of that date and feeds the Evaluate rule. `academy/rendezvous.py`:
  propose a date (at most five years ahead, fitting open Predictions) and a save name, move it, and answer "before it /
  at it / after it (missed)" for a given newest save. Tests per rule.
  Done: before a decision the extract announces only a Tradition tree (Unity covers the next Tradition, a tree slot is
  free) and an Ascension Perk (a slot is free); after, two Snapshots show a new tree, a new perk, a war the Tracked
  Empire attacked in, a changed designation. Megastructures and federations are not in the extract: named in
  `NOT_DETECTABLE`, never found, the Player can still state a Prediction on them. A Prediction with a measurable
  `expect` (extract path, operator, number) is decided by code from the first Snapshot at or after its date; without
  one the Player's verdict is stored (`decided_by` `player`). Only `confirmed` by a Snapshot on a foretold Prediction
  lifts its concepts to Evaluate; hindsight expectations and Player verdicts never do. Rendezvous: two years ahead at
  a month start (placeholder), never beyond five years or before the latest open check date; "at" means the newest
  save lies 0 to 30 days after the date. Details in the module docstrings of `academy/predictions.py` and
  `academy/rendezvous.py`. `drill.copy_events` is public now (the check writes to the Campaign's `evidence.jsonl`).

## Risks

| Risk | What we do |
|---|---|
| Too few Remedies carry `applied_when`, so almost nothing reaches Apply | Increment 20c reports coverage; the unchecked Remedies keep the Coach asking and the level at Understand, which is correct, not a failure |
| The model reports the wrong outcome (calls a guess a cause) | The tool checks `support` against the Snapshot, the skill gives examples per outcome, the review-blocks skill keeps its role; Julian's trial is the real test |
| Hidden Fair Play knowledge leaks through a hint | Topics carry visible pointers only, tested; the claim check (M7) sees the tool results |
| Direct writes to the Player Model | The hook blocks Write, Edit and Bash on the path; the store verifies `model.json` against the events on every read |
| A game patch changes the graph | The patch rule compares two pack versions; with only 4.5.2 shipped it is tested on synthetic packs |
